A claim, end to end

What happens between clicking Adjudicate in ui/index.html and seeing the decision badge. Step tags match the blue pills on the diagram.

  1. S

    When a pod starts, it gets AWS credentials through IRSA 10 and reads the OpenAI key and RDS password from Secrets Manager 9.

  2. R1

    The browser uploads the PDF with POST /v1/claims/adjudicate to the ALB 1 on port 80, then keeps the connection open to read a Server-Sent Events stream.

  3. R2

    The ALB forwards to one app pod 15 on :8000, straight to the pod IP. It only sends traffic to pods passing /healthz.

  4. R3

    The pod saves the file to /tmp/documents/<run_id>/ and starts the agent graph. Intake looks up ocr:<sha256 of file> in Redis 7.

  5. R4

    On a cache miss, Textract reads the PDF 6 through the NAT gateway 3. The result goes back into Redis, so the same file is never OCR'd twice.

  6. R5

    Validate, repair and adjudicate. Adjudicate pulls the top 6 policy chunks from pgvector and the member's earlier decisions from long-term memory, both in RDS 8. Every step saves a checkpoint to RDS, so a run can be resumed.

  7. R6

    The model decides. Adjudicate and audit call OpenAI 20 (gpt-4.1-mini) through the NAT gateway. If audit rejects the reasoning, it sends the claim back for another attempt.

  8. R7

    The answer streams back. Each step sends node_start/node_end events; the last event, final, carries the decision and its cost. The decision is also stored in RDS.

intake→ validate⇄ repair ≤2→ fallback→ adjudicate⇄ audit (heal)→ final

The agent graph inside each pod. Fallback runs only when OCR fails or repair runs out of attempts, and then the decision is MANUAL_REVIEW.

Onboarding a policy

Policy text reaches the agents only through the vector store in RDS. Changing it means uploading to S3, then running the seed job again. Step tags match the green pills on the diagram.

The seed job reads exactly three file names

It downloads everything under s3://<bucket>/policies/, but only ingests:

  • policy_wording.pdf: each clause starts with a [Clause XX-N.N] marker
  • member_handbook.pdf: paragraphs headed Related to clause XX-N.N
  • procedure_code_annexure.pdf: the procedure-code table

A file with any other name is downloaded and then ignored. To update a policy, replace the file with the same name. Adding a new kind of document needs a code change in pipelines/data_pipeline.py.

  1. P1

    Upload the PDF to the documents bucket 11 under policies/.

  2. P2

    Re-create the seed job 16. Jobs can't be re-run in place, so delete the old one first.

  3. P3

    An init container copies policies/ from S3 into the job's scratch volume, using the pod's IRSA role 10.

  4. P4

    The job splits the text by clause and embeds each chunk with OpenAI 20 text-embedding-3-small, through the NAT gateway 3.

  5. P5

    Chunks are written to pgvector in RDS 8. The next claim retrieves the new text with no pod restart.

# PowerShell, repo root, after Step 2 of the run guide ($IMAGE set)
$BUCKET = (Get-Content .tf-outputs.json | ConvertFrom-Json).documents_bucket.value
aws s3 cp .\policy_wording.pdf "s3://$BUCKET/policies/"                     # P1

kubectl delete job seed-data -n claim-adjudication --ignore-not-found     # P2
(Get-Content k8s/job-seed-data.yaml -Raw) -replace '__ECR_REPOSITORY_URL__:__IMAGE_TAG__', $IMAGE | kubectl apply -f -

kubectl wait --for=condition=complete job/seed-data -n claim-adjudication --timeout=900s
kubectl logs job/seed-data -n claim-adjudication -c seed-data              # P3–P5 output + verify
  • Safe to re-run. Chunks are deduplicated by content hash, so unchanged clauses are skipped.
  • Old wording is not removed. Edited clauses are added as new chunks next to the old ones. The pipeline's purge command clears them, but there is no Kubernetes Job for it yet.
  • Costs a few cents. Embedding is the only paid step.

Build, deploy and watch

  1. D1

    Build and push the image to ECR 5. Nodes pull :latest every time a pod starts, so kubectl rollout restart picks up a new push.

  2. D2

    Run the db-migrate Job 17 once per database to create the tables in RDS 8.

  3. Ops

    Watch it. Prometheus 19 scrapes agent latency, tokens and cost from /metrics; view them in Grafana. Cluster and database logs go to CloudWatch 12, and Budgets 13 emails when spend passes $50.

  4. IaC

    Terraform owns everything AWS except the ALB, which the LB Controller 18 creates. State lives in S3 with a DynamoDB lock 14. Teardown: scripts/destroy_all.sh.

Known limits on AWS today

  • No HTTPS and no login.The ALB listens on plain HTTP :80 and the API has no authentication. Anyone with the URL can submit claims. Fine for a short training run, not for real data.
  • The knowledge graph is not loaded by the app.The seed job builds it inside its own pod, and the app pods never see that file. On AWS, retrieval uses the vector half only.
  • Uploaded PDFs are temporary.They live in the pod's /tmp and disappear on restart. A resume request can land on the other pod, which doesn't have the file.
  • Long silent steps get cut off.The ALB closes a connection after 60 seconds without data.
  • Autoscaling can't scale yet.The cluster has no metrics-server, so the HPA can't read CPU and stays at 2 pods.
